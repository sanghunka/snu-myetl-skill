# 자연어 요청을 실제 학습 준비로 연결하기

## 작업 폴더와 과목 연결

과목을 찾을 때는 `courses` 결과의 학기 정보와 등록 상태를 함께 읽는다. API에서 활성으로 보이는 과목이 모두 이번 학기 과목인 것은 아니다. 사용자가 지정한 학기·과목 목록이 있으면 그 기준을 적용한다. 학기 정보가 없고 여러 학기가 섞였을 때에만 선택에 필요한 질문을 한다.

사용자가 지정한 저장 위치를 우선한다. 새 과목 폴더는 과목명으로 만들고, 이름이 같은 과목은 과목 코드나 ID를 덧붙여 구분한다. 슬래시·제어문자는 파일 경로에 안전한 문자로 바꾸고, 한국어 파일명은 NFC로 정규화한다. 기존에 쓰는 폴더가 있으면 `과목 목록.md`의 연결을 유지한다.

예시 구조는 다음과 같다. 모든 하위 폴더를 먼저 만들 필요는 없으며 실제로 저장하는 자료에 맞춰 만든다.

```text
학업/<학기>/
├── 과목 목록.md
├── 이번 학기 한눈에 보기.md
├── 학기 일정.md
└── <과목명>/
    ├── 강의계획서/
    ├── 자료 목록.md
    └── 자료/
        └── <모듈명>/
```

`과목 목록.md`에는 과목 ID·과목명·학기·폴더·eTL 과목 링크를 기록한다. 인증정보와 다운로드용 임시 URL은 기록하지 않는다.

## 강의계획서 찾기

1. `GET /courses/<과목ID>?include[]=syllabus_body`를 조회한다.
2. 본문에 첨부 파일이나 페이지 링크가 있으면 함께 확인한다. `data-api-endpoint`나 `/courses/<과목ID>/files/<파일ID>` 링크를 활용한다.
3. 본문이 비어 있으면 페이지 목록, 모듈 항목, 파일 목록에서 `강의계획서`, `실래버스`, `syllabus`, `course outline`을 찾는다.
4. API에 연결되지 않은 안내 링크만 있으면 원문 위치를 기록한다. 인증이 필요한 외부 자료를 받은 것으로 보고하지 않는다.
5. HTML 본문은 목록·표·링크의 의미를 유지한 Markdown으로 저장하고, PDF·문서 파일은 원본도 보존한다.

본문을 정리할 때는 원문 전체를 읽는다. 긴 문서를 일부만 읽고 나머지 내용이나 평가 방식을 추정하지 않는다. 저장 문서에 확인한 eTL 링크와 조회 시각을 남긴다.

## 교수·조교 정보와 학기 안내표

강의계획서, 과목의 교수 정보, 공개된 사용자 프로필을 교차 확인한다. 교수 API가 연구실·오피스아워까지 구조화해 제공한다고 가정하지 않는다. 이메일이 없으면 강의계획서의 연락처를 찾고, 어느 자료에도 없으면 `미기재`로 남긴다.

| 과목 | 교수·조교 | 이메일 | 연구실 | 오피스아워 | 교재 | 평가 방식 | 출처 |
|---|---|---|---|---|---|---|---|
| 확인한 과목 | 원문에 기재된 이름 | 기재된 주소 | 기재된 장소 | 요일·시간·예약 조건 | 서명·판본 | 시험·과제·출석 비중 | eTL 링크 |

정규 수업 시간과 오피스아워를 구분한다. 평가 비중 합계가 맞지 않거나 서로 다른 안내가 충돌하면 해당 원문들을 함께 표시하고 임의로 수정하지 않는다.

## 자료 일괄 저장과 동기화

1. 모듈 목록을 받은 뒤 각 모듈의 항목 목록을 마지막 페이지까지 조회한다.
2. `File`은 `content_id`를 파일 ID로 사용한다. `Page`는 본문을 저장하고 연결된 파일을 찾는다. 과제·공지의 첨부자료도 사용자가 요청한 범위라면 파일 ID를 찾아 처리한다.
3. 파일 목록은 보완 자료로 사용한다. 모듈에 연결된 파일을 먼저 분류하고, 그 밖의 공개 자료는 `기타 자료`로 구분한다.
4. 외부 URL과 외부 도구는 제목·원문 위치를 자료 목록에 기록한다. 문서 다운로드와 외부 도구 실행을 같은 작업으로 처리하지 않는다.
5. 동일 파일 ID의 중복 항목은 한 번만 받고 자료 목록에서 연결한다. 처음부터 여러 모듈 폴더에 중복 저장하지 않는다.
6. `download`에 `--course-root`로 과목 폴더를 지정한다. 파일 ID·수정 시각·크기·해시가 일치하면 건너뛰고, 원격 수정이나 로컬 변경이 있으면 기존 파일을 보존한 새 이름으로 저장한다.
7. 전송 완료와 크기 확인이 끝난 파일만 성공으로 기록한다. 실패 항목에는 이유와 원문 링크를 남긴다.

```bash
python3 <스킬폴더>/scripts/canvas_api.py get /courses/<과목ID>/modules
python3 <스킬폴더>/scripts/canvas_api.py get /courses/<과목ID>/modules/<모듈ID>/items
python3 <스킬폴더>/scripts/canvas_api.py download <파일ID> --destination '<과목폴더>/자료/<모듈명>' --course-root '<과목폴더>'
```

다운로드 기록은 `--course-root`로 지정한 과목 폴더의 `.snu-myetl/downloads.json`에 남는다. 모듈명·배치가 바뀌어도 과목 폴더와 파일 ID로 기존 자료를 찾아 재사용한다. 같은 파일이 다른 모듈에 나타나면 자료 목록에서 기존 저장 경로를 연결한다. 파일을 직접 옮겼다면 기록과 실제 경로를 다시 대조한다. 단일 파일 다운로드에서 `--course-root`를 생략하면 저장폴더 안에 기록한다.

변경사항을 이어서 확인하는 요청에서는 공지·페이지·과제 메타데이터의 이전 상태를 학기 폴더의 `.snu-myetl/조회 기록.json`에 저장한다. 비교에 필요한 ID·제목·수정 시각·마감일·제출 상태와 비교 기준 시각만 기록한다. 첫 실행에는 현재 상태를 기록하고, 다음 실행부터 차이를 보고한다. 전체 목록을 성공적으로 조회했을 때만 해당 목록의 기준 상태를 갱신한다. 일부 과목 실패를 빈 목록으로 덮어쓰지 않는다.

## 일정과 이번 주 할 일

플래너와 캘린더에서 일정을 모으고 과제·퀴즈·토론 상세 정보를 대조한다. UTC를 `Asia/Seoul`로 변환한 뒤 날짜를 비교한다. 같은 과제는 과목 ID와 과제 ID로 중복을 제거한다.

과제의 `include[]=submission` 응답 또는 `/submissions/self`에서 본인의 상태를 읽는다. `unsubmitted`는 미제출, `submitted`·`pending_review`는 제출됨으로 처리한다. `graded`는 점수가 있다는 이유만으로 실제 파일 제출이 있었다고 단정하지 않고 `submitted_at`, 첨부파일, 과제 유형을 함께 확인한다. 마감일이 없는 과제와 제출이 필요 없는 항목을 별도로 표시한다.

공지는 게시 시각과 본문에 적힌 적용 날짜를 구분한다. 휴강, 강의실 변경, 준비물, 추가 읽기, 과제 마감 변경을 행동 항목으로 정리한다. 공지와 과제의 마감일이 충돌하면 양쪽 출처를 보여주고 확정되지 않은 변경을 단정하지 않는다.

`학기 일정.md`에는 등록된 일정과 강의계획서에 명시된 일정만 넣는다. 정확한 날짜가 없는 주차별 시험 안내는 해당 주차로 표시한다. 이미 올라온 모든 자료를 시험 범위로 추정하지 않는다.

## 자료 내용 검색과 시험 준비

파일명·모듈 제목으로 후보를 찾고, 요청에 필요한 원문을 읽어 내용으로 확인한다. 결과에는 과목·주차·파일명·쪽수 또는 제목·eTL 링크를 함께 제공한다. 자료를 변환할 수 없으면 확인하지 못한 범위를 알린다.

시험 준비는 공지·강의계획서의 명시된 범위와 해당 자료를 연결한다. 학습 목차와 읽기 순서는 제안할 수 있지만 확정된 출제 범위와 구분해 표현한다.

## 결과 형식

- 저장 결과: 과목, 파일명, 저장 경로, 크기, 신규·수정본·기존 여부.
- 동기화 결과: 새 자료, 새 수정본, 이미 받은 자료, 잠금 자료, 실패 항목 수.
- 할 일: 과목, 마감일, 본인 상태, 해야 할 행동, 원문 링크.
- 누락 정보: 미기재, 자료 없음, 권한 제한, 조회 실패를 각각 구분.

시간 절감이나 정확도는 직접 측정한 값만 보고한다. 예시 데이터의 결과를 실제 eTL에서 확인한 결과로 표현하지 않는다.
